Privacy policy — Zaim Organizer Gmail

Effective September 30, 2026. This application is for the operator's own household ledger. No public user registration is offered.

Access and purpose

The sole Google permission is gmail.readonly. This permission technically allows mailbox reading; the implementation restricts each weekly run to receipt and order-confirmation searches from the last 100 days, at most 100 messages. It reads selected sender, subject, date, authentication headers and inline message text. It does not download attachments, visit links in messages, or retain recipient/CC headers in its preview.

Use

Data is used only to identify purchases, review receipt formats, and support the operator's existing ledger classification rules after validated transaction matching. Data is not used for advertising, sold, used for credit decisions, or sent to language-model APIs. Human review is limited to the owner and an assistant explicitly authorized by the owner to review receipt evidence.

Storage and service providers

OAuth refresh credentials and receipt previews are encrypted. Credentials are stored locally in ignored private files and encrypted GitHub repository secrets. Receipt previews may be processed by GitHub Actions and stored as encrypted artifacts in a private repository for three days. Google serves the requested Gmail data and OAuth tokens; GitHub hosts the authorized private execution and encrypted storage. Ordinary logs contain aggregate counts and status codes rather than email text or credentials. The public website contains no receipt, ledger, or authentication data.

Retention and control

Each fetch replaces the local encrypted preview; cloud receipt artifacts expire after three days. The operator can delete local files, GitHub secrets and artifacts, disable the scheduled job, and revoke the app's access through Google Account third-party connections at any time. Revocation stops future Gmail access; existing files must also be deleted if desired.

Limited Use

Zaim Organizer Gmail's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

Questions: use the project issue tracker without posting private records or credentials. Material changes to data practices require an updated policy and the owner's authorization.
